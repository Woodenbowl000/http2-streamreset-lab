Shared mitigation state (one blocklist at the guard, for both attacks)

"Mitigate Rapid Reset" targets the source actually attributed to that signal — the guard counts client-sent RST_STREAM frames per source IP, a deliberate signal only Rapid Reset produces — so it correctly blocks that attacker even while a different source is running MadeYouReset at the same time. "Mitigate MadeYouReset" intentionally does not use per-source server-reset counts to pick a target: confirmed experimentally that Tomcat sends genuine server-side resets as an ordinary side effect of a fast-backend Rapid Reset flood too, so that signal alone can't reliably tell the two attacks' sources apart. It falls back to blocking whichever source currently holds the most live connections instead of claiming a precision it doesn't have.
